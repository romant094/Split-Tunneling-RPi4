# Quick Task 260820-lo0 — Logs selection ergonomics

Follow-up to `260820-kcg`. Design approved in conversation.

## Task 1 — Row checkboxes in select mode, Select All as a tri-state checkbox

**Files:** `src/admin/src/pages/Logs.jsx`, `src/admin/src/App.css`

**Action.**
1. `LogBox` renders a checkbox at the left of each row while `selectMode` is on.
   Clicking the row still toggles it, so nothing that worked before stops working.
2. The row becomes a flex container: checkbox plus a `white-space: pre` span for
   the text. The fixed 19.2px row height must survive — the virtualizer's
   `estimateSize` depends on it.
3. The checkbox is `position: sticky; left: 0`. Rows scroll horizontally now
   (`260820-kcg`), so a statically positioned checkbox would slide off the left
   edge as soon as the user scrolled right.
4. `SelectionBar` replaces the `Select All (N)` button with the tri-state
   `Checkbox` from `components/ui/checkbox.jsx` — unchecked when nothing is
   selected, indeterminate for a partial selection, checked when all visible rows
   are selected. Same component and semantics as the Routes table header.

**Verify.** `npx oxlint src`, `npm run build`.

**Done.** Selecting rows is discoverable rather than a hidden click target, and
Select All reads its state instead of only offering an action.

## Task 2 — `Add all` dropdown with a confirmation dialog

**Files:** `src/admin/src/pages/Logs.jsx`

**Action.**
1. New `Add all ▾` button in the toolbar, next to `Select`. Built on `Popover`
   (already a dependency) with two items: `Add to ISP routes` and
   `Add to VPN routes`.
2. Acts on the **current visible set** — after include filters, exclude filters
   and Hide duplicates. Select mode is not required; this is the "I have filtered
   the view down to what I want, take all of it" path.
3. Disabled when the visible set is empty or yields no routes.
4. Confirmation dialog for every size, not only large ones: shows
   `N lines → M routes`, the destination list (ISP or VPN), and a scrollable list
   of the CIDRs with their descriptions. `Cancel` / `Add M routes`.
   Unfiltered, the visible set can be thousands of lines and hundreds of /24s, so
   the count has to be visible before the click commits.
5. After confirmation the existing staging path is reused, so the routes appear
   under Pending changes on the Routes page and are not applied until
   Apply Changes.
6. Both sub-pages, Watch Live and Historical.

**Verify.** `npx oxlint src`, `npm run build`.

**Done.** A filtered view can be turned into staged routes without entering
select mode, and the number of routes is stated before anything is staged.
