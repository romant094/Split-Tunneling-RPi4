  <action>
    Create `scripts/routing.sh` as a Bash script with `#!/usr/bin/env bash` and `set -euo pipefail`. Model structure, logging, and idempotency patterns from `scripts/install-awg.sh`.

    **Preamble:** Comment block listing decisions honored (D-01 through D-10), invocation contract (sudo bash /etc/routing.sh or with --no-update), and env source (/etc/vpn-gateway.env).

    **Source env:** `source /etc/vpn-gateway.env` near top. Variables used: KEENETIC_GW, VPN_SERVER_IP, VPN_IFACE (should be "awg0"), LAN_SUBNET, RU_SUBNET_URL.

    **Argument parsing:** Check for `--no-update` flag in `$*`. Set `SKIP_DOWNLOAD=false` by default; `SKIP_DOWNLOAD=true` if flag present. (D-05)

    **Define log()/err() functions:** Same pattern as install-awg.sh — log() prefixes with `[routing]`, err() prefixes with `[routing] ERROR:` and goes to stderr.

    **Stage 1 — Download subnet list (D-03, D-04, ROUT-01):**
    - If `SKIP_DOWNLOAD=true`: log "skipping download (--no-update), using existing /etc/vpn-ru-subnets.txt" and jump to Stage 2.
    - Otherwise: `curl -fsSL "${RU_SUBNET_URL}" -o /etc/vpn-ru-subnets.txt` with a temp-file strategy (download to `/tmp/ru-subnets.tmp`, then `mv` to `/etc/vpn-ru-subnets.txt` on success). On download failure: if `/etc/vpn-ru-subnets.txt` exists, log a warning and continue (D-04 fallback); if file is missing, `err` and exit 1 (D-04 abort).

    **Stage 2 — Validate subnet file:** Check `/etc/vpn-ru-subnets.txt` exists and is non-empty. Count lines with `wc -l`. Log count.

    **Stage 3 — Flush existing routes (D-06, ROUT-02):**
    - `ip route flush dev "${VPN_IFACE}" 2>/dev/null || true` — removes all routes (including default) that use awg0.
    - `ip route del "${VPN_SERVER_IP}/32" 2>/dev/null || true` — remove the VPN server host route (lives in main table via ISP, not via awg0, so flush above doesn't touch it). Use `/32` suffix for precision.
    - `ip route del default 2>/dev/null || true` — safety: remove any remaining default route before we set ours.
    Log: "routes flushed, rebuilding..."

    **Stage 4 — Add VPN server host route (ROUT-03, D-01):**
    `ip route add "${VPN_SERVER_IP}/32" via "${KEENETIC_GW}"` — this must be added BEFORE the default via awg0 to prevent the tunnel loop. (D-01: main table)

    **Stage 5 — Add RU subnet routes (ROUT-01, D-01, D-02):**
    Loop over `/etc/vpn-ru-subnets.txt`: for each non-empty, non-comment line, run `ip route add "${subnet}" via "${KEENETIC_GW}" 2>/dev/null || true`. The `|| true` handles any subnet already present from a prior partial run (belt-and-suspenders on top of the flush). Log total added count.

    **Stage 6 — Set default route via VPN (ROUT-04, D-09):**
    `ip route add default dev "${VPN_IFACE}"` — all non-RU traffic exits VPN. (Added after RU routes so the host route and RU routes take precedence in longest-prefix match.)

    **Stage 7 — iptables MASQUERADE (NAT-01, NAT-02, D-07, D-10):**
    For each interface in (awg0, eth0):
    ```
    iptables -t nat -C POSTROUTING -o <iface> -j MASQUERADE 2>/dev/null \
      || iptables -t nat -A POSTROUTING -o <iface> -j MASQUERADE
    ```
    Log result for each interface (added or already present).

    **Stage 8 — iptables-persistent (NAT-03):**
    - Install: `dpkg -l iptables-persistent 2>/dev/null | grep -q '^ii' || DEBIAN_FRONTEND=noninteractive apt-get install -y iptables-persistent`
    - Save rules: `mkdir -p /etc/iptables && iptables-save > /etc/iptables/rules.v4`
    - Log: "iptables rules saved to /etc/iptables/rules.v4"

    **Stage 9 — Verification log:**
    Print current routing state for the operator:
    - `ip route show default`
    - `ip route get "${VPN_SERVER_IP}"` (should be via KEENETIC_GW)
    - `ip route get 8.8.8.8` (should be dev awg0)
    - `ip route get 77.88.8.8` (should be via KEENETIC_GW — a well-known RU IP in the subnet list)
    These are informational — failures here are not script errors.

    **Final log:** "routing.sh complete — split-tunnel active"

    Script must NOT bring up or down the awg0 interface. Must NOT assume a TTY. Must be safe to run under `sudo bash /etc/routing.sh`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| RU subnet URL (opencck.org) | External data source; downloaded content is used as route destinations |
| iptables rule injection | Script runs as root; malformed subnet file could cause unexpected routes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-02-01 | Tampering | RU subnet download (opencck.org) | mitigate | Downloaded to temp file first; mv to /etc/vpn-ru-subnets.txt only on success; D-04 fallback uses existing file if download fails |
| T-02-02 | Tampering | /etc/vpn-ru-subnets.txt contents | mitigate | File contains only CIDR strings used as `ip route add` destinations; invalid CIDRs cause ip route to error (non-fatal with || true); no shell execution of file contents |
| T-02-03 | Denial of Service | ip route flush dev awg0 | accept | Brief routing gap during flush-rebuild (~milliseconds per D-06); RPi4 can process 5000 routes in <5 seconds |
| T-02-04 | Elevation of Privilege | Script runs as root via sudo | mitigate | set -euo pipefail fails fast; no eval or dynamic command construction from downloaded data; subnet file used only as `ip route add` argument |
| T-02-05 | Tampering | iptables-persistent apt install | mitigate | Uses DEBIAN_FRONTEND=noninteractive; pinned to distro package; no curl-bash |
</threat_model>
