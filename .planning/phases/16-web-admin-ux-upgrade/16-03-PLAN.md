<objective>
Fix UI-AUTH client-side (RESEARCH root cause): the SPA currently gates login on `sessionStorage` and always re-sends `Authorization: Basic ...`, so a new tab or browser restart re-prompts even when a valid `sg_session` cookie exists. Switch to a cookie-first model that probes `/api/auth/check` on mount.

Purpose: The backend cookie (Phase 15 D-09, now with Max-Age from plan 16-01) already persists; the frontend must actually rely on it.
Output: Updated `src/admin/src/api.js` and `src/admin/src/App.jsx`; committed `dist/` rebuild.
</objective>
