  <action>
    Create a module-level singleton store for pending route additions keyed by list. Internal state: `pending = { vpn: [], isp: [] }` where each entry is `{cidr, description}`. Export:
    - `subscribe(fn)` — registers a listener, immediately invokes it with current state, returns an unsubscribe function (mirror logStream.js).
    - `stageAdd(list, entry)` — where `list` is `'vpn'|'isp'`; appends `{cidr, description}` if the cidr is not already pending in that list; notifies subscribers.
    - `stageAddMany(list, entries)` — batch version (used by Logs multi-select in plan 16-07; 16-06 is the Diagnostics page, not Logs).
    - `unstage(list, cidr)` — removes a pending entry; notifies.
    - `getPending(list)` — returns the current array for a list.
    - `clearPending(list)` — empties one list (called after a successful Apply); notifies.
    Do not persist to storage — this is in-memory session staging matching the Routes-page pending pattern (CONTEXT D-05).
  </action>
