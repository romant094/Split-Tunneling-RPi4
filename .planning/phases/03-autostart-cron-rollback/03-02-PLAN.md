<objective>
Add daily auto-refresh of the RU subnet list to the gateway. Every day at the hour configured by `CRON_UPDATE_HOUR` (default 5), a cron job runs `/etc/update-vpn-routes`, which downloads the current list, compares its SHA256 against the file already on disk, and only flushes + rebuilds routes (`/etc/routing.sh --no-update`) when the upstream list has actually changed. On the ~majority of days when the list is unchanged, the script exits silently — zero disruption to active connections.

Purpose: Without this slice, the RU subnet list freezes after the last manual `/etc/routing.sh` run. Country-level routing decisions drift out of date within weeks. The checksum-based approach gives daily freshness without the cost of nightly route flushes when nothing changed (D-06).

Output: New script `scripts/update-vpn-routes` (deployed to `/etc/update-vpn-routes`), new env var `CRON_UPDATE_HOUR=5` in `.env`, and two new deploy.sh stages that SCP the script and generate `/etc/cron.d/vpn-routes` from the env var.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| macOS → RPi (SCP) | scripts/update-vpn-routes and the generated cron line cross over SSH (BatchMode=yes, key auth). |
| cron daemon → /etc/update-vpn-routes | crond reads /etc/cron.d/vpn-routes and execs the command field as root. Any non-root user with write access to either file could escalate. |
| /etc/update-vpn-routes → external HTTP (RU_SUBNET_URL) | Cron-driven outbound HTTPS GET to russia.iplist.opencck.org via the RPi's ISP route (the ISP route is pinned in routing.sh Stage 4 as `${VPN_SERVER_IP}/32 via ${KEENETIC_GW}` — but the RU URL is foreign, so the request actually goes via the VPN). Response body is a list of CIDRs written to /etc/vpn-ru-subnets.txt. |
