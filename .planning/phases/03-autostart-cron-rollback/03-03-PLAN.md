<objective>
Deliver a single-command rollback that fully undoes the VPN gateway — stops services, flushes routes, removes NAT rules, removes the cron job, and restores direct ISP default routing — in one idempotent execution. After this plan the operator can recover the RPi to plain-host routing at any time without reinstalling anything.

Purpose: The gateway is reversible by design (core project constraint). This plan delivers ROLL-01 and ROLL-02: a named rollback script at /etc/vpn-rollback.sh that undoes all running state from Phases 1–3 while preserving all installed packages and config files so the gateway can be re-activated simply by re-running ./deploy.sh.

Output: New script `scripts/vpn-rollback.sh` (deployed to `/etc/vpn-rollback.sh`) and deploy.sh extended to Stage 16 to SCP it. Phase 3 is fully complete after the human-verify checkpoint confirms rollback restores plain ISP routing.

    **Step 1 — Stop + disable vpn-routing.service (D-08 order):**
      - `log "Stopping vpn-routing.service..."`
      - `systemctl stop vpn-routing.service 2>/dev/null || true`
      - `systemctl disable vpn-routing.service 2>/dev/null || true`

    **Step 2 — Stop + disable awg-quick@${VPN_IFACE} (D-08):**
      - `log "Stopping awg-quick@${VPN_IFACE}..."`
      - `systemctl stop "awg-quick@${VPN_IFACE}" 2>/dev/null || true`
      - `systemctl disable "awg-quick@${VPN_IFACE}" 2>/dev/null || true`

    **Step 3 — Flush VPN interface routes (D-08; Pitfall 4):**
      - `log "Flushing routes on ${VPN_IFACE}..."`
      - `ip route flush dev "${VPN_IFACE}" 2>/dev/null || true`
      - `ip route del "${VPN_SERVER_IP}/32" 2>/dev/null || true`
      - `ip route del default 2>/dev/null || true`
      (All three with `|| true` — Pitfall 4: set -e must not abort before the restore-default step below)

    **Step 4 — Remove MASQUERADE rules (D-08; mirrors routing.sh Stage 7 pattern inverted):**
      - `log "Removing MASQUERADE rules..."`
      - For ${VPN_IFACE} (awg0): `if iptables -t nat -C POSTROUTING -o "${VPN_IFACE}" -j MASQUERADE 2>/dev/null; then iptables -t nat -D POSTROUTING -o "${VPN_IFACE}" -j MASQUERADE; log "MASQUERADE on ${VPN_IFACE}: removed"; fi`
      - For eth0: `if iptables -t nat -C POSTROUTING -o eth0 -j MASQUERADE 2>/dev/null; then iptables -t nat -D POSTROUTING -o eth0 -j MASQUERADE; log "MASQUERADE on eth0: removed"; fi`

    **Step 5 — Re-save iptables without MASQUERADE rules (Pitfall 5 tolerance):**
      - `netfilter-persistent save || log "WARNING: netfilter-persistent save failed — rules removed from kernel but may reload on reboot"`
      (The `||` prevents set -e from aborting if netfilter-persistent is not installed; MASQUERADE is already removed from the running kernel either way)

    **Step 6 — Remove cron entry (D-08):**
      - `log "Removing cron entry..."`
      - `rm -f /etc/cron.d/vpn-routes`
      - `log "Cron entry removed: /etc/cron.d/vpn-routes"`

    **Step 7 — Restore ISP default route (D-08, Claude's Discretion: static, no dhclient):**
      - `log "Restoring ISP default route via ${KEENETIC_GW}..."`
      - `ip route add default via "${KEENETIC_GW}"`
      - `log "Default route restored: default via ${KEENETIC_GW}"`

    **Step 8 — Final state summary to stdout (D-09):**
      - Print a clearly delimited summary block (see RESEARCH.md Pattern 4 for the exact format).
      - Summary must list: Stopped and disabled services, Routes flushed, NAT rules removed, Cron removed, Default route restored via, Preserved (not removed) files, and "To verify: ip route show default  — Expected: default via ${KEENETIC_GW}".

    Anti-patterns to avoid (per RESEARCH.md):
      - Do NOT use `ip route flush table main` — only flush `dev ${VPN_IFACE}` routes (Anti-Patterns section)
      - Do NOT use dhclient — static `ip route add default via ${KEENETIC_GW}` (Anti-Pattern + D-08 confirmed)
      - Do NOT remove awg0.conf, /etc/routing.sh, /etc/vpn-ru-subnets.txt, or any AmneziaWG packages (ROLL-02, D-10)
      - Do NOT call `iptables -D` without the `-C` guard — may error if rule was already absent

    File must be executable (chmod +x locally; deploy.sh enforces chmod +x on the RPi).
