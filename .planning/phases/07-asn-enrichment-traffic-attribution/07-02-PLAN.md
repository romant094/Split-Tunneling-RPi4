<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| vpn-status.sh → /etc/asn-lookup.py (subprocess) | IPs piped on stdin originate from kernel iptables LOG entries (already validated as IPv4 by routing.sh LOG rule format); no shell expansion of dst_ip in the subprocess call |
| /etc/asn-lookup.py → /tmp/vpn-asn-cache.json | Shared cache file; mode 0o666 by Plan 01 design |
| vpn-status.sh inline `python3 -c` parse | Receives JSON from asn-lookup.py stdout — same trust level as asn-lookup.py itself (root-owned binary on RPi) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-06 | Tampering | dst_ip value piped to python3 subprocess | mitigate | dst_ip is extracted via `grep -oP 'DST=\K[0-9.]+'` — regex already restricts to digits+dot; piped via `printf '%s\n'` (no eval); python3 reads as plain string |
| T-07-07 | Denial of Service | python3 -c hangs on malformed JSON from asn-lookup.py | mitigate | inline python3 `json.loads(sys.stdin.read())` raises ValueError caught by `|| true` on the bash side; org_map left empty → all ORG cells become `-` |
| T-07-08 | Information Disclosure | `--summary` output reveals org-level traffic distribution | accept | Tool runs on operator's own RPi; output not exposed externally; same exposure surface as existing vpn-status.sh |
| T-07-09 | Tampering | Stale cache holds incorrect ASN (BGP reassignment) | accept | Per CONTEXT.md D-02: no TTL by design — BGP ASN assignments are stable; user can `rm /tmp/vpn-asn-cache.json` to force refresh |
</threat_model>
