## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-written exception file → kernel routing | CIDRs read from /etc/white-list-extended.txt are passed to `ip route add` as positional arguments — no eval, no shell expansion of file content |
| Filesystem path migration | Old /etc/vpn-ru-subnets.txt may still exist on the RPi as a stale orphan after first deploy of Plan 01 changes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | routing.sh Stage 5b reads /etc/white-list-extended.txt | mitigate | Reuse T-02-02 pattern: CIDR values passed as args to `ip route add`, no eval; malformed entries suppressed by `2>/dev/null \|\| true` (matches Stage 5 trust model) |
| T-05-02 | Tampering | /etc/white-list-extended.txt written by non-root process could inject routes | mitigate | Plan 02 deploys the file with chmod 644 root:root via `sudo mv` + `sudo chmod 644` + `sudo chown root:root` — only root can modify the file on the RPi |
| T-05-03 | Denial of Service | User adds VPN_SERVER_IP/32 (or covering supernet) as an exception, creating a routing loop | accept | Stage 4 host route for VPN_SERVER_IP/32 (added by routing.sh) is more specific than any CIDR a user is likely to add; even an exception covering the VPN server is fine because /32 wins over /N (longest-prefix match). Documented in 05-RESEARCH Security Domain table. |
| T-05-04 | Information Disclosure | Stale /etc/vpn-ru-subnets.txt left on RPi after rename | accept | File is harmless data (publicly-fetched RU CIDR list, no secrets); routing.sh no longer reads it after Plan 01 deploy. User-driven cleanup (rm) is acceptable; no automated removal in rollback because rollback only undoes running state per ROLL-02. |
| T-05-05 | Tampering | Stage 5b log counter EX_ADDED could be confused with Stage 5 ADDED in scripts that parse logs | accept | Counters log distinct prefixes ("RU subnet routes added:" vs "Exception routes added:"); no consumer currently parses these lines. |
| T-{phase}-SC | Tampering | npm/pip/cargo installs | n/a | Phase 5 installs no packages — Standard Stack section of 05-RESEARCH confirms "No New Packages". RESEARCH Package Legitimacy Audit explicitly states "No packages are installed in this phase". |
</threat_model>
