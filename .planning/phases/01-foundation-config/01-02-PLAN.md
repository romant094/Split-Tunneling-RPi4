<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local filesystem → deploy.sh process | `.env.secrets` is the trust root for VPN keys; must remain mode 600 (user responsibility) and gitignored (Task 1) |
| deploy.sh process → SSH tunnel to pi4 | SSH (key auth per D-06) provides confidentiality + integrity; host alias `pi4` resolves via `~/.ssh/config` |
| `/tmp/awg0.conf.tmp` on RPi (post-SCP, pre-sudo-mv) | Window where rendered config exists at non-root path; mitigated by immediate `sudo mv` + chmod 600 + chown |
| Rendered config on local disk (mktemp) | Plaintext keys present briefly on macOS; mitigated by `chmod 600` immediately AND `trap ... rm -f` on every exit path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-SEC | Information Disclosure | AWG_PRIVATE_KEY in rendered awg0.conf | mitigate | `mktemp` + `chmod 600` BEFORE write; `trap 'rm -f "$tmp"' EXIT`; sed via shell-variable expansion (no command-line arg exposure per RESEARCH.md Pitfall 7); never SCP `.env.secrets`; remote file ends as `chmod 600 root:root` |
| T-01-GIT | Information Disclosure | Accidental commit of `.env.secrets` | mitigate | `.gitignore` entry `.env.secrets` (Task 1); template file `.env.secrets.example` shipped instead so the developer never has reason to commit the real file |
| T-01-PERM | Tampering | Permissions on `/etc/amnezia/amneziawg/awg0.conf` on RPi | mitigate | Explicit `sudo chmod 600 && sudo chown root:root` after `sudo mv`; WireGuard refuses to start with looser permissions (defense in depth) |
| T-01-MITM | Tampering | Keys + config in transit to RPi | mitigate | SSH/SCP encrypted by default with host key verification; D-06 mandates pre-configured SSH key auth (no password fallback) |
| T-01-PARTIAL | Denial of Service | Partial deploy on validation failure | mitigate | Preflight validation (Stages A, C, D) runs BEFORE any remote mutation; `set -euo pipefail` halts on first error; Stages G/H are write-then-sudo-mv (atomic on RPi) |
| T-01-PS | Information Disclosure | Keys in process list | mitigate | Shell-variable expansion inside `sed -e "s|...|${VAR}|"` — the expanded value is the sed argv but exec is brief and inside the script's own process tree; per RESEARCH.md Pitfall 7 this is acceptable; alternative would be sed reading a separate script file which adds disk-exposure risk |
| T-01-INSTSC | Tampering | Streamed installer payload (Stage E) | mitigate | Plan 01's `scripts/install-awg.sh` is checked into git (reviewable); `ssh "sudo bash -s" < scripts/install-awg.sh` transmits over SSH (encrypted, integrity-protected) — no `curl | bash` from deploy.sh side |
</threat_model>
