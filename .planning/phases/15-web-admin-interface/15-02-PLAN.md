STEP 2 — Create src/admin/src/api.js:

  Shared API helper. Stores credentials in sessionStorage (key: 'sg_auth', value: JSON {user, pass}).
  On the first successful login, the Flask backend (Plan 01) sets an HttpOnly sg_session cookie via the
  Set-Cookie response header. All subsequent requests on the same origin — including EventSource — send
  this cookie automatically because they use credentials: 'include' / withCredentials: true.

  Implement:
    - LOGIN_STORAGE_KEY = 'sg_auth'  (stores {user, pass} as JSON in sessionStorage)
    - function getAuth() -> {user, pass} | null from sessionStorage
    - function setAuth(user, pass) -> stores in sessionStorage
    - function getAuthHeader() -> 'Basic ' + btoa(user + ':' + pass)
    - async function apiFetch(path, options={}) -> adds Authorization: Basic header AND credentials: 'include'
      so the browser stores the Set-Cookie sg_session from the response; returns fetch Response
    - async function apiLogout() -> POST /api/auth/logout with credentials: 'include';
      then removes sg_auth from sessionStorage

  Do NOT implement buildSseUrl or any URL containing user:pass@host.
  EventSource authentication is entirely handled by the sg_session HttpOnly cookie set by the server.
  Chrome 59+ (and all modern browsers) reject userinfo in URLs per the WHATWG Fetch spec; the cookie
  approach is the correct cross-browser solution.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser sessionStorage → API | Credentials stored in sessionStorage; lost on tab close |
| EventSource → /api/logs/watch | withCredentials:true sends sg_session HttpOnly cookie; no credentials in URL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-10 | Information Disclosure | Credentials in sessionStorage | accept | LAN-only tool; sessionStorage cleared on tab close; no persistent storage |
| T-15-11 | Information Disclosure | sg_session cookie | accept | HttpOnly; SameSite=Strict; in-memory server-side only; LAN-only; clears on service restart |
| T-15-12 | Tampering | Client-side CIDR validation bypass | mitigate | Client-side validation is UX only; server validates with CIDR_RE (Plan 01 Task 1) |
| T-15-13 | Denial of Service | Log lines filling browser memory | mitigate | Logs.jsx caps logLines at 1000 with slice(-1000) on each append |
| T-15-SC | Tampering | npm package installs | mitigate | checkpoint:human-verify (Task 1) gates npm install; only 3 canonical packages used |
</threat_model>
