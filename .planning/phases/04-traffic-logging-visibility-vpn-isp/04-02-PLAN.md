  <action>
    Create scripts/vpn-status.sh. Mark it executable (chmod +x) after creation.

    Script structure (following D-17 patterns):

    HEADER COMMENT: Purpose, deployed path (/etc/vpn-status.sh), usage examples including
    flags, list of decisions honored (D-11–D-17).

    SHELL OPTIONS: set -euo pipefail

    LOGGING: log() { logger -t "vpn-status" "$*"; } — same pattern as update-vpn-routes.

    ENV SOURCE: Guard block checking /etc/vpn-gateway.env exists, then source it. Same
    pattern as routing.sh (err + exit 1 if missing).

    DEFAULTS:
      LAST=50
      FILTER=""
      DEVICE=""

    ARG PARSING: Loop over "$@" parsing --last=N (validate N is a positive integer via
    [[ N =~ ^[0-9]+$ ]]), --filter=STRING (store as-is), --device=IP (store as-is).
    Reject unknown flags with err() + exit 1.

    JOURNALCTL QUERY (D-12, D-13):
    Fetch iptables LOG lines from kernel journal:
      journalctl -k --no-pager -n "${LAST}" -g '\[(VPN|ISP)\]' 2>/dev/null

    This produces lines like:
      May 21 12:00:01 pi4 kernel: [VPN] IN=eth0 OUT=awg0 MAC=... SRC=192.168.1.50 DST=8.8.8.8 ...

    Parse each matching line to extract:
      - ts: timestamp field (fields 1-3 via awk/cut)
      - decision: "VPN" or "ISP" (grep -oP '\[(VPN|ISP)\]' | tr -d '[]')
      - src_ip: SRC= field value (grep -oP 'SRC=\K[0-9.]+')
      - dst_ip: DST= field value (grep -oP 'DST=\K[0-9.]+')

    Apply --device filter immediately after extraction: skip lines where src_ip does not
    match ${DEVICE} (when DEVICE is non-empty).

    DOMAIN RESOLUTION (D-13, two-step):
    For each connection entry (dst_ip + ts + src_ip), resolve domain name:

    Step 1 — dnsmasq log correlation:
      Query journalctl -u dnsmasq --no-pager for lines containing the dst_ip OR a query
      from the same src_ip within the same 60-second window. Search for dnsmasq log lines
      matching "query\[" and the src_ip, extract the queried hostname. Use journalctl
      --since and --until based on the connection timestamp minus/plus 30 seconds.
      Practical approach: extract all dnsmasq query lines for src_ip in a broader window
      (--since "5 minutes ago"), store in a temp variable, then grep for dst_ip in those
      query responses (dnsmasq logs both "query[A] hostname from src_ip" and
      "reply hostname is dst_ip"). Match by looking for "reply <hostname> is <dst_ip>"
      in the dnsmasq output.

    Step 2 — rDNS fallback (D-13):
      If Step 1 finds no domain: run `host "${dst_ip}" 2>/dev/null` and extract the
      hostname from the last line via grep -oP '\S+\.arpa\. domain name pointer \K\S+'.
      Strip trailing dot if present. If rDNS also fails: domain = "${dst_ip}" (raw IP).

    Apply --filter: skip entries where domain does not contain ${FILTER} (case-insensitive
    grep -i). Apply after domain resolution so filter works on resolved names.

    OUTPUT FORMAT (D-12):
    Print a header line:
      printf "%-20s %-18s %-18s %-40s %s\n" "TIMESTAMP" "SRC-IP" "DST-IP" "DOMAIN" "PATH"
      printf "%-20s %-18s %-18s %-40s %s\n" "--------------------" "------------------" "------------------" "----------------------------------------" "----"

    For each resolved entry, print one line:
      printf "%-20s %-18s %-18s %-40s %s\n" "${ts}" "${src_ip}" "${dst_ip}" "${domain}" "${decision}"

    Truncate domain to 40 chars if longer (use ${domain:0:40}).

    If no entries after filtering, print: "(no connections matched — try --last=200 or remove filters)"

    IMPORTANT: vpn-status.sh is a query/display tool run interactively by the operator.
    It must NOT exit non-zero when there are simply no results. It MUST exit non-zero on
    actual errors (missing env file, invalid args, journalctl unavailable).

    Do NOT hardcode interface names. Use ${VPN_IFACE} where needed (sourced from env).
    Do NOT produce fenced code blocks in this action.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator CLI → vpn-status.sh args | --filter, --device, --last values from operator; used in grep/awk, not eval |
| dnsmasq → journald | dnsmasq writes DNS query log lines; vpn-status.sh reads them via journalctl |
| external DNS response → domain display | resolved domain names displayed to terminal; never executed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04 | Tampering | dnsmasq.conf server=1.1.1.1 | accept | upstream is hardcoded Cloudflare; no runtime override from LAN devices |
| T-04-05 | Information Disclosure | dnsmasq query log in journald | accept | journald on RPi only; accessible to root; no external export in this phase |
| T-04-06 | Elevation of Privilege | vpn-status.sh runs as root (sudo) | accept | read-only journalctl queries; no writes to system state; standard operator tool |
| T-04-07 | Injection | --filter/--device values used in grep | mitigate | values passed as grep -F (fixed string) or pipe filter — not passed to eval, sh -c, or iptables |
</threat_model>
